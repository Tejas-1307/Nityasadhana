1. PROJECT VISION & CORE PHILOSOPHY
--------------------------------------------------------------------------------
Nityasādhanā (नित्यसाधना — "Eternal Sādhanā") is a high-performance, mobile-first 
spiritual companion and discipline management platform created for ISKCON 
devotees, ashrams, and Brahmacharya training programs.

Current manual methods rely heavily on fragmented WhatsApp messages and manual 
Excel sheets, creating heavy administrative burden for Gurus and tedious typing 
friction for Shishyas (students). 

Nityasādhanā replaces manual spreadsheets with a calm, sacred, and lightning-fast 
digital environment designed with two core non-negotiable principles:
1. Zero Gamification: No competitive leaderboards, no peer rankings, no artificial 
   purity scores. Progress is purely reflective: "YOU Today vs. YOU Previously".
2. Extreme Speed: Daily reporting must take under 30 seconds with minimal tapping,
   zero unnecessary typing, and intelligent memory defaults.

2. TECHNOLOGY STACK & INFRASTRUCTURE
================================================================================
The entire application is engineered on a modern, ultra-lightweight, and secure 
full-stack foundation:

* Framework: Next.js 15.1.7 (React 19) utilizing the App Router architecture.
* Language & Types: 100% Strict TypeScript (Zero `any` in core domains).
* Styling & Design System: 
  - Custom Tailwind CSS design tokens and custom CSS variables.
  - Ancient Gurukul + Vrindavan Aesthetic: Warm Ivory (#F7F1E5), Krishna Blue 
    (#2457A6), Gurukul Saffron (#D9822B), Forest Green (#3D765B), Charcoal (#20201D).
  - Typography: Nunito Sans (clean modern legibility) + Noto Serif Devanagari 
    (authentic sacred Sanskrit glyphs).
* Icons & Visuals: Lucide React (feather-weight SVG icons).
* Charts & Graphs: 100% Zero-Dependency Custom SVG Micro-Charts. No heavy chart 
  libraries (e.g. Chart.js or Recharts) to preserve an ultra-lean ~105 kB initial bundle.
* Authentication & Security: Clerk Authentication (Next.js App Router v6) + 
  Server-authoritative Role-Based Access Control (RBAC).
* Data Layer: In-memory/File-backed relational store with strict transactional 
  isolation, composite unique constraints, and cryptographic token verification.

4. HOW OUR CODE WORKS: ARCHITECTURE & DATA FLOW
================================================================================

1. Server-Authoritative Security & Role Enforcement:
   - Client-side role claims are completely ignored.
   - When a page or server action executes, `requireShishya()` or `requireGuru()` 
     extracts the session user from `@clerk/nextjs/server` and verifies the trusted 
     server role.
   - If unauthenticated or unauthorized, the user is immediately redirected to `/login`.

2. Calculation Engine (`lib/reports/calculations.ts`):
   - `calculateSleepDuration(sleepTime, wakeUpTime)`: Handles cross-midnight UTC 
     arithmetic accurately (e.g. 21:30 to 03:45 = 375 minutes).
   - `calculateReportConsistency(reports, todayDateStr, windowDays)`: Computes rolling 
     calendar compliance from submitted reports only (drafts are strictly excluded).
   - `calculateJourneyAnalytics({ reports, rangeDays, todayDateStr })`: Chronologically 
     bins data into Current Period [T ... T-(N-1)] and Previous Period [T-N ... T-(2N-1)], 
     calculating threshold-filtered deltas and daily time series.

3. Optimized Server Actions (`lib/actions/`):
   - Next.js Server Actions execute securely on the server with direct access to the 
     data layer, avoiding traditional client-side fetch waterfalls.
   - Operations like `submitDailyReportAction()` or `getStudentJourneyDataAction()` 
     return typed `{ success: boolean, data?: T, error?: string }` responses.

4. Database Layer (`lib/db/store.ts`):
   - Enforces unique compound constraints: `(studentId, practiceDate)`.
   - Indexing by `studentId` and descending `practiceDate` for $O(1)$ and $O(K)$ lookups.
   - Cryptographic invitation verification with expiration and one-time-use validation.
